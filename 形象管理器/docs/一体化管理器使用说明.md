# Data 与形象管理器使用说明

本工具支持已识别的曹操传加强版 6.5、6.6 数据与图片资源。使用“打开项目”选择包含 Data.e5、Star.e5、Imsg.e5、Ekd5.exe 的基底目录。

## 数据编辑与迁移

一体化 data 管理器的“图片设定 → 场景背景（Mmap.e5）”提供“地形编辑”。点击内场景（第41项起）打开菱形地形弹窗，勾选“显示地形”后左键标记障碍、右键清除，支持按住拖动；“显示网格”独立控制边线，右下角显示当前场景坐标。Ctrl+滚轮缩放，Ctrl+Z/Y 按笔撤回/重做，Ctrl+S 保存；关闭有修改的弹窗时可保存、放弃或取消。Pmap 独立图库在一体化管理器中隐藏，地形通过专用 UInt16 编码写回。新增/复制内场景和删除内场景同步维护 Pmap，外场景删除改为黑色占位并保留前40个槽位；内场景删除前须核对剧本编号引用。

左侧选择 ID：名称，右侧编辑当前记录。编辑先进入草稿，顶部“保存”统一提交关联文件；撤回、前进和历史记录分别支持草稿及已保存操作。

一体化 data 管理器保存人物 R/S 编号后，会自动同步当前项目相关磁盘存档中的本次人物及字段；替换、导入或像素修改 R/S 图片即时保存时，也会按已保存的人物指定同步关联存档。其他人物的剧情形象保持原样。人物页未保存草稿继续保留，图片同步不会提前保存这些草稿。成功同步的存档、统计和索引与本次主修改进入同一历史，可整次撤回和重做。坏档、未知扩容、关联校验不符或被占用的存档组会跳过，界面报告“已更新、已一致、已跳过”及逐档原因；部分未同步时仍保留已保存的形象。此功能默认启用，支持经过当前引擎和格式验证的原生 E5S、两种已知战场统计格式和当前版本自动存档；不修改 EXS 或游戏进程内存。

文本按游戏使用的严格 GBK／CP936 编码计算容量，汉字通常占 2 字节，英文和数字通常占 1 字节。名称旁显示剩余字节，列传、说明和台词显示已用、上限及剩余字节；将鼠标停在提示上可查看当前槽位的容量和依据。容量同时受物理槽、终止符、原槽非零保留数据和已确认的游戏读取方式限制。不能用字符数量代替字节数量，也不能把表内槽宽直接当成可输入容量。已确认的列传槽支持完整 200 个 GBK 字节，不固定减为 199 字节。

超过容量的键入、粘贴或输入法提交会整次拒绝，保留原文及选区，不截取前一部分保存。GBK 无法表示的字符和 NUL 不会被问号代写；单行名称也不接受含换行的粘贴。原始基底已有长度或编码异常时会明确提示，未修改该字段仍保留原始字节；主动编辑时须修复异常后再保存。

仍在当前文本框中、尚未失去焦点的输入会由顶部“保存”一起收集。切换人物、模块或物理表前会先检查当前编辑，验证失败时保留草稿并停留在原处。普通／特殊暴击模式、类型及槽位切换前会保留原先台词行的修改；修改共享普通台词会影响同类型人物。特殊槽已被他人占用时，必须显式确认覆盖，不能通过切换选择绕过冲突检查。聚焦文本框时，Ctrl+Z／Ctrl+Y 优先撤回／重做尚未提交的文本；离开文本编辑后使用统一草稿撤回栈。

兵种系“辅助分组”属于同一份未保存草稿，顶部“保存”和分组页“校验保存”均统一提交分组及其他数据修改。页面动态显示分组负载已用、剩余字节，并另保留安全边界；容量不足的新增、勾选或导入会拒绝，空分组须填写或删除后才能保存。分组新增、删除、勾选和 CSV 导入均可使用顶部“撤回／前进”，草稿撤回不会写入文件。保存前会核对文件 SHA-256，合并同文件修改，再校验、写入和复读；失败时保留可修正的草稿，已进入写入阶段的失败会尝试恢复提交前文件；文件锁、外部修改或磁盘故障阻止恢复时会列出失败项。

CSV 按物理表导出，保留布局元数据，中文列名可以重新导入当前兼容项目。未知数值可按当前字段边界输入；只读字段会显示原因。

一键迁移方向是“源基底 → 目标基底”。先查看差异，再选择覆盖、跳过或合并。源目录只读，目标先在临时副本中写入、复读，通过后备份并提交。特效号、特效值和分配关系按逻辑字段迁移，特效名称池按策略跳过；目标不支持的拓展物品保留目标内容并列出诊断。

## 图片设定

左侧名称括号内标明资源出处。R、S、头像、图标、范围、动画、天气、地形和地图按各自的格式读取。人物、宝物和策略页只预览关联图片，实际资源替换在图片设定完成。

S 形象图库分“将领”和“兵种”，均按 Unit 文件的物理图号顺序逐张展示。兵种固定槽为 `S_001～S_240`；将领为 `S_241` 起至三个档案的共同末尾。每项只包含当前物理号的 11 个移动帧、12 个攻击帧、5 个特技帧，缩略图固定显示移动第 0 帧；查看全部帧、播放、编辑和复制均操作当前单张物理图，不把相邻图号合成多转形象。

人物数据里的“S形象编号”使用工具整合包的紧凑编号，与图库物理号分开：编号 0 使用当前兵种我军；编号 1～32 每号占连续三个物理图，编号 `s` 的第一转图号为 `241+3×(s−1)`，后两转顺次加 1、加 2；编号 33 起每号占一张，图号为 `s+304`。例如人物编号 1 的三张图是 241～243，人物编号 32 是 334～336，人物编号 33 是 337。人物下拉及人物详情只预览对应编号第一转的移动第 0 帧；编号 0 只预览当前兵种我军单张。图库的 `S_242` 是物理图号，不能把 242 直接当作上述人物紧凑编号。

兵种物理图号 `p` 的兵种 ID 为 `(p−1)/3` 的整数商，阵营由 `(p−1)%3` 决定，余数 0／1／2 分别为我／友／敌军。例如 `S_001` 是兵种 0 我军，`S_002` 是兵种 0 友军，`S_004` 是兵种 1 我军。前 60 个兵种 ID 已含转职信息；每三个连续 ID 为同兵种系的一、二、三转，后 20 个 ID 为单转兵种。兵种详情按 ID `j` 从上到下同时显示物理 `3j+1`、`3j+2`、`3j+3` 的移动第 0 帧；某阵营缺图或损坏会在该位置单独提示，不借用其他阵营图。

兵种S卡片标题统一为“兵种ID：兵种名称 我/友/敌军”，例如山贼项目“0：群英 我军”“0：群英 友军”“0：群英 敌军”“1：诸侯 我军”。名称按详细兵种表同ID读取，从兵种0开始；图号与导出目录仍使用Unit物理号，可继续搜索`S_001`等物理编号。

兵种导入、替换与清空保持固定物理号，禁止追加。将领物理删除只删除选中的图号，包括 241～336 区间内的单张图；程序列出所选图号和会前移的后续范围，人物 Data 引用不会自动调整。复制追加只把所选将领物理图的完整 28 帧同步追加到 mov／atk／spc 三档案末尾；三档案数量不一致时拒绝追加。

Cmdicon.dll 按稀疏原生 ID 逐项显示独立位图；文件替换按所选 ID 的实际画布与 DIB 编码转换，新增每张素材追加一个原生 ID 并采用目标 MOD 已确认的模板规格，删除只移除所选 ID，其他 ID 与内容保持不变。宝物／策略图标仍按大小图对处理。

“导出图片”导出原始尺寸、原始帧序的竖向动作条，供直接修改与替换。R 每套两个文件：front.bmp、back.bmp，均为 48×1280，分别从上到下放置 20 个 48×64 帧，仍使用 `R000` 等目录。S 每项三个文件：mov.bmp 为 48×528，含 11 个 48×48 帧；atk.bmp 为 64×768，含 12 个 64×64 帧；spc.bmp 为 48×240，含 5 个 48×48 帧。将领物理 242 导出到 `将领/S_242/`，兵种物理 2 导出到 `兵种/S_002/`。“导出单帧”把同一项的 PNG 放在对应目录，例如 `将领/S_242/S_242_atk_000.png`。替换动作条时严格检查提供文件的尺寸、帧数和帧序；可以只提供需要修改的动作，未提供动作保持不变，不将整条插值缩放为单帧。

“导出参考图”按当前选中物理图号导出参考总图和 AI 提示词，例如 `将领/S_242.png`、`兵种/S_002.png`；每张 S 总图只包含同一物理号的完整 28 帧。R 总图继续使用 `R000.png` 等命名。参考图应保持提示词规定的原始画布像素尺寸、帧数、格位、动作顺序、透明或键色背景及像素风格；每格只画一帧，不添加标题、边框、网格、阴影、抗锯齿或额外人物，不合并和移动格子。

S 原生动作条与参考总图导入前须明确选择“物理编号”或“旧编号”格式，对话框会列出素材名与目标物理号。物理格式直接使用 `S_242`／`S_002`；旧版将领文件 `S002` 对应物理 `240+2=242`，旧版兵种文件 `兵种S001` 对应物理 `1+1=2`。这里兼容的是旧版逐张导出文件的编号，不是人物 Data 的紧凑编号，也不把旧多转总图展开写入多个图号。批量导入必须逐项匹配所选格式的名称和目录，不自动猜测零基／一基；单项导入允许直接选择素材目录或任意命名的 PNG，但目标始终是当前选中的物理图号，应先核对映射。

导回参考图时优先接受与导出一致的无损 PNG。放大的 AI 图片先按固定格位拆帧，再用最近邻还原到原始帧像素网格并量化到目标调色板；默认不做模糊卷积，也不强制把 AI 新形象的轮廓、大小、中心或底部拉成原人物的轮廓。仅在格式不一致时启用必要的几何自动修复，并在预览中标明修复与裁切。改动服装、武器、身形后仍保留 AI 的新内容；原图用于动作和格位参考。写入前检查原图、AI 图、修复结果、最终调色板帧和动画；缺帧、越格或无法确认的输入必须先修正。

文件新增和替换统一进入“图片导入”窗口。普通静态素材支持 BMP、PNG、JPG、JPEG、GIF、TIF、TIFF、ICO、WebP，不要求素材的色深或文件名等于目标；程序按实际文件内容解码。GIF、TIFF、ICO、WebP 按首帧、首页面或首目录项作为静态图片导入，详情中注明来源格式与帧选择；这不是大小动画导入。R/S 素材限 BMP、PNG、JPG、JPEG，继续严格检查标准尺寸与帧数；其余静态图片接受任意尺寸，自动适配目标 MOD 规格。可逐槽选图、粘贴路径或从目录自动识别；重复候选保留为待分配项。未知文件名可明确指定动作和目标，也可主动按待分配列表顺序分配。在待分配列表的“更多”中点击“同一图片应用到所选槽”可显式复用素材，兵种多阵营也逐个列出最终物理图号。

映射完成后点击“准备转换并预览”，核对来源、当前目标、转换后图片、尺寸和输出格式，再“确认写入”。准备阶段不修改项目或历史；某行出错时须修正或明确排除后重新准备，整批通过后才一次提交。R/S 可查看整条和逐帧结果。换源或修改映射会使旧预览失效；素材、目标档案或调色板在预览后变化时拒绝旧候选。

转换预览中的“写入格式”默认 BMP，也可选择 PNG 或保留原格式。普通标准 E5 使用 BMP24/PNG32，标准 R/S 动作条使用 BMP32/PNG32；保留原格式时，替换沿用目标实际编码，新增沿用末尾同类、同动作模板。BMP使用游戏透明键色，非零半透明按RGB实色写入，PNG保留其透明通道。已确认RAW8、DLL/DIB、天气、Pmap和地图等专用结构按原结构编码，并显示限制原因；图标提供BMP与保留原格式。RAW按项目调色板量化并保留合法尾部，未知结构拒绝写入。普通E5按目标画布最近邻适配；头像居中裁切，标准Face选择BMP/PNG时使用120×120规格，保留原格式时沿用原画布；Tou按各语言变体实际画布和DIB结构处理。

R/S动作条仍严格保持原生尺寸与帧数，不缩放、补帧或重排；新增R须正背成对，新增S须移动/攻击/特技完整组并保持三个Unit档案等长及240个兵种固定槽。替换可只分配所需动作，其他动作和相邻物理号保持。切换格式会取消旧转换并自动更新预览，只有最新候选准备成功才能确认。目录与识别工具仅在“素材映射”；空的待分配列表自动收起，可拖动分隔条调整。预览页显示当前目标、源图和实际候选，长路径、编码及裁切说明在“详细信息”中查看。

6.6 RAW大小动画统一按项目调色板展开；Mcall尾部遗留色表保留原字节，不再用它覆盖颜色。山贼Mcall00的火龙颜色已修正，首尾透明渐变保留。标准BMP/PNG动画仍使用自身颜色。

头像接受任意尺寸，标准 Face 中心裁正方并以高质量双三次缩放到120×120 PNG；已识别旧版头像按其实际尺寸和编码处理。Face/Tou 从同一原素材分别生成，Tou 保留各变体的尺寸、色深及语言，不从缩小后的Face放大。选中 Face0 替换时，映射表单独列出“表情0～7（中心裁切）”；每个表情可选择任意命名、任意尺寸的静态素材，选图后自动勾选。只写入已分配并勾选的表情与对应 Tou 项，其他表情保持；表情目录角色须手动指定。

宝物和成对策略图标接受任意尺寸，先识别透明/近洋红背景（DLL另识别纯蓝），非标准尺寸裁出有效内容、等比最近邻居中到实际大图画布；素材已等于目标画布时保留留白。未给小图时从完整大图派生：E5最近邻，DLL的两倍尺寸对使用透明优先2×2硬采样。可显式指定小图；大小图一起写入。E5图标输出24位BMP洋红底，DLL按各目标8/24/32位DIB编码，转换效果以候选预览为准。

文件导入与像素编辑分别处理：原像素编辑仍保留尺寸、编码、调色板、未修改索引和合法尾部，小图像素编辑继续使用既有透明感知卷积。复制编辑追加及参考图保持各自协议。已确认 RAW、天气和 Pmap 可在统一窗口使用专用编码器转换；未知尾部或未确认结构拒绝写入。PNG 可作为无损交换格式；AI 图片不要转存 JPG。

像素编辑窗口中点击“换色”，可配置五组原色→目标色。每组的原色和目标色旁都有“取色”：点击后换色窗口暂时隐藏，在主底图上左键选择当前像素，颜色自动回填该组并更新命中数。可以滚动底图、调整缩放或使用 Ctrl+滚轮查看像素；右键或 Esc 取消本次取色并返回换色窗口。动作之间的空隙、画布外和边框不参与取色，网格及动作文字不影响取到的底图颜色。

透明像素可作为原色或目标色，完全透明的像素统一计数和替换；非索引资源保留半透明颜色的 Alpha。索引资源的非透明目标色会匹配到项目调色板中的最近颜色，透明目标与橡皮效果相同。配置换色期间暂停绘图、撤回、重做和保存；点击“同时替换”后整批规则一次应用，可整体撤回或重做，点击“取消”保留底图草稿。最后在像素编辑窗口点击“写回当前”或允许的“复制完整形象并追加”才提交游戏资源。

地图的“替换图片”只转换底图：任意尺寸静态素材自动生成当前地图画布的 JPG，Hexzmap 地形层不变。“导入地图与地形”保留目录成对导入：同名 `Mxxx.BMP` 是专用地形网格，必须保持原始格数与结构；底图可用同名 JPG、PNG 等其他格式。底图本身为 BMP 时另用文件名，例如 `Mxxx_image.bmp`，避免与地形 BMP 混淆；有多个底图候选时须先明确来源。

天气已确认的 43200 字节条目支持新增和替换，任意尺寸素材自动适配 216×200 整条，再按项目调色板量化；从上到下对应四个 216×50 帧。新增追加到末尾，禁止删除或重命名编号。Pmap 已验证模板同样支持新增和替换，自动匹配目标画布与调色板，逐字节保留其16字节专用头，禁止删除或重命名编号；Pmap 像素编辑暂不可用。地图仍使用现有固定槽，不能直接追加。Meff、Mcall 大小动画继续使用完整动画包入口与原有结构校验，静态首帧素材不会代替其播放记录或动画帧平面。

动画预览按当前格式的帧尺寸、帧数和记录引用顺序循环播放。已验证 Weather 条目为 216×200 的竖条，按从上到下四个 216×50 帧循环；大、小动画按容器内实际记录、RAW 平面或嵌入位图拆帧，支持已确认的调色板、位置和透明度变化，不能套用天气的四帧常量。游戏场景背景与特殊辅助遮罩保留，预览会标明相应边界。暂停后可检查单帧；无法确认格式时显示明确诊断，不把整个帧条或非像素头数据当成一张图播放。

新增通常追加，删除可能使后续编号前移；程序会在操作前提示已知引用风险。资源新增、替换、删除及其他确认后的资源操作会立即写回，进入统一已保存历史；顶部“保存”主要提交数据草稿。资源操作前会核对相关文件的 SHA-256，写入后复读验证；验证或历史记录建立失败会尝试恢复操作前文件，并明确报告恢复受阻的路径。若文件已被其他工具修改，会停止操作并提示冲突，不覆盖外部修改。需要撤销已经写回的资源操作时使用“历史撤回”，检查相应记录和文件指纹后恢复；“历史前进”可重做。

## 常用快捷键

Ctrl+S：保存数据；Ctrl+Z / Ctrl+Y：撤回 / 前进。
Ctrl+Alt+Z / Ctrl+Alt+Y：历史撤回 / 历史前进，作用于已经保存的数据及资源操作。
Ctrl+N：新增图片；Delete：删除或清空图片；Ctrl+I：替换图片；Ctrl+E：导出图片。
Ctrl+Shift+E / Ctrl+Shift+I：导出 / 导入参考图。
Space：播放动作；F4：全部帧；Ctrl+P：像素编辑；F2：批量改名。
Ctrl+A：选择当前筛选结果；F5：刷新资源；F1：显示本内置说明。

## 单文件版本

图片导入兼容版为 Windows x64 框架依赖单文件，需要 .NET 8 Windows Desktop Runtime x64。发布目录仅需一个 EXE；游戏数据、资源、导出文件、备份及历史仍保存在项目目录，不写入程序本身。程序放在只读目录时仍可打开并编辑有写入权限的项目。
