# 6.4 图像适配与验证

基底：`基底/洗隋`。测试只读原始文件，全部保存与历史操作在系统临时目录执行，不启动游戏。

## 身份与人物指定

- `ProjectVersion.Ccz64 = 3`；旧 `Unknown=0 / Ccz65=1 / Ccz66=2` 保持原值。PE 数字私有版本 4 优先于 DLL 图标资源特征；显示版本为 6.4。
- 洗隋 EXE SHA-256：`91121D4B5F7FBB987475943A590B76308C0DDB8B6BCD17C218EEDC6568CE2AD8`。
- 当前 EXE 的 R 消费者文件 `0x8438` 读取 `UInt16[ID*2+0x50F800]`，PE 映射为文件 `0xE1000`。其人物 ID 函数文件 `0xB27D` 证明运行时人物指针差除以 72。
- S 消费者文件 `0x5CD9` 读取 `UInt16[ID*2+0x501000]`，映射为文件 `0xD2800`；同时验证完整函数的 ID<1024、0/33 形象分支和 0xFFFF 返回。两表必须完整处于唯一可写 PE 节、各1024×UInt16且互不重叠。
- 不使用 EXE SHA 白名单开放指定写入。有效编辑只修改表值，SHA 改变后消费者仍能证明布局；未知/截断/被改坏的消费者拒绝指定表读取和保存，图像容器仍分别探测。

## 实际容器

首末逻辑资源解码覆盖27个资源目录：R、S、Face、Itemicon、Mgcicon、Cmdicon、Logo、Mmap、Gate、Hitarea、Effarea、U_select、Meff、Pmap、Weather、地图配对、Mcall00～08、BUFF与ts。R为375组；S将领510个物理槽；Face为514条物理图片、507个逻辑头像（头像0含八表情）；宝物/策略/命令DLL图标分别150/49/41项。缺少Tou时使用现有小头像模式。

洗隋 `Face.e5` 的前八条JPEG被旧工具重定向到文件末尾，不能用第一条载荷偏移决定目录长度。增加仅适用于 Face.e5 的恢复分支：要求 Ls12 头、连续合法目录、显式四字节零尾、全部为未压缩标准图片、引用区完整且互不重叠。普通 E5 保持原严格目录规则。重建时保留所有514条有效图片的原载荷，取消已无索引引用的旧载荷；不直接修改原始样本。

## 自动验证

在工作区根目录执行：

```powershell
dotnet run --project '形象管理器/src/ImageManager.Tests/ImageManager.Tests.csproj' -- --ccz64
```

结果：4组通过、0失败，包括6.4实际容器与R/S验签/副本事务，以及6.5、6.6和六套6.6指定表回归。具体检查：版本枚举稳定、移除路径提示仍识别6.4、人物/兵种/策略读取、全部实际容器首末项解码、R字段候选仅修改目标UInt16、提交后复读、撤回逐字节恢复、前进恢复候选、改变消费者/越界地址/截断PE拒绝、重定向Face全部514条重建载荷保持、损坏Face地址拒绝。所有原图像/核心文件前后SHA一致。

这组验证确认离线图像工具行为；游戏内显示与整合交付的运行验收另由正式游戏副本完成。
