# 人物档位：五维阈值、6.5 强化成长掩码与静态扫描矩阵

本文补齐“人物/五维档位”此前未闭环的 6.5 `0x41A534 → 0x41A596 → 0x42518F` 链路，并给出 26 个真实基底的只读静态扫描结果。

结论以本地 6.4 洗隋、6.5 加强版未加密版、6.6 复刻版6.6山贼为准；所有扫描只读 `Ekd5.exe`，未修改游戏文件。

## 一、结论速览

- 属性档位（单维）有三套实现：
  - **direct-threshold**：`0x4072F2` 直接比较 `单位+0x21..0x25` 的原始属性，返回 1..6 或 1..7。
  - **6.5-threshold+mask**：`0x41A534` 先算阈值档位，再用“强化成长”特效掩码给对应维 `+2`。
  - **6.6-table / 6.6-correction**：`0x4072F2` 查阈值表 `0x4CFA00`，或直接阈值后调用修正函数 `0x436E3D`。
- 最终档位 = `floor((兵种档位 + 属性档位) / 2)`；每级成长和显示都使用这个合并值。
- 6.5 的“强化成长”掩码位序已确认：
  - bit0=攻、bit1=防、bit2=精、bit3=爆、bit4=士。
  - bit 置位 → 该维档位 `+2`；`0x1F` 显示“全能力”。
  - 标准 6.5 的特效号是 `0xC6..0xCE`（名称池均为“强化成长”，尾部 `0x09`=五属性组合）。
  - 十八州演义是变体：单特效 `0xB2`“能力提档”，尾部同样是 `0x09`，位测试逻辑相同。
- 26 个真实基底中，19 个可稳定识别档位路径（全部 PASS），7 个因加壳/无函数/非标准入口无法静态定位。

## 四、变体与静态扫描

扫描器：`工具整合包/静态分析/scan_character_tier.py`；矩阵：`人物档位静态扫描矩阵.csv`（26 行）。

### 4.1 识别规则

- 函数入口：`55 8B EC 8B 45 08 3C 04`。
- direct-threshold：函数体内有 `8A 44 08 21`，后接 `3C imm / 7C|72 04 / B0 value` 阈值链。
- 6.6-table：函数体内有 `3A 90/88/80 <imm32>`，且 imm 指向以 0/1 开头的阈值表。
- 6.5-mask：
  - 标准链：9 个 `push C6..CE` + 共同 `call`，且 tier 函数调用该掩码函数。
  - 内联变体：`push eax; push 0; push 0; push 0; push <id>; call`，后接 `test eax,eax / mov ecx,[ebp+8] / shr eax,cl / and eax,1 / shl eax,1 / add [ebp-4],eax`。
  - 语义门：掩码特效尾部为 `0x09`（五属性组合）。
- 6.6-correction：tier 函数内 `E8` 目标为 `0x436E3D`。
- 显示表：6.4 `0x472DDB`、6.5 `0x472DD7`、6.6 `0x4CF400`；检查指针可读并解出文本。

- 19 个可定位基底全部 `Status=PASS`，`DisplayOk=True`，`CallSites`/`MergeSites` 均大于 0。
- 7 个无法定位的基底：3 个加壳、3 个无质变/档位函数、1 个非标准入口；扫描器明确标记 `UNKNOWN`，不会误写。
- 变体差异被记录而不是强行套版本：例如“刘备6.4”实际是 6.6 表格机制，“厚黑6.6”是自定义 direct-threshold，“复刻版6.6”是 direct-threshold + correction。

### 4.3 可行性结论

- 静态扫描对三套主路径 **可行且可复现**；标准 6.4/6.5/6.6 与主要改版均能定位函数、阈值、掩码/修正与调用点。
- 矩阵为 26 行，`19 PASS / 7 UNKNOWN`；两次 `--all` 输出 SHA256 均为 `807E336DF5401BEBC7AC7DC1767A16C6B9C145FA16C9FF708139CA33307E1127`。
- 扫描器只读，不依赖游戏运行；对加壳/无函数基底安全失败。
- 显示表使用版本固定地址，改版若搬移显示表会显示 `DisplayOk=False`，需要人工补地址；这不影响成长/合并逻辑的扫描。
- 静态无法证明“某个单位当前实际生效哪个 C6..CE 槽位”，只能证明查询顺序与掩码语义；实际槽位取决于运行时效果列表。
