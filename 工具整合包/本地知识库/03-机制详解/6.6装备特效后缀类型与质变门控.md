# 6.6 装备特效后缀类型与质变门控（0x4CB6BA）

## 结论速览

- 6.6 的 `0x004CB6BA` 是**每特效号 1 字节**的表，索引 `特效号 - 0x1A`，范围 `0x1A..0x87`（`0x6E` 字节）。
- 该字节有**两个消费者**：
  1. 质变函数 `0x004200F5` 在 `0x00420147` 读取：值 `<7` 时应用 `×3/2`，`≥7` 时跳过。
  2. 装备特效后缀格式化函数 `0x0046215B` 在 `0x004621BA` 读取：决定装备界面显示的后缀文本。
- 因此它不是单纯的“是否跳过 ×1.5”开关，而是**后缀类型 + 成长门控**共用字节。
- 覆盖表 `0x004CB5CA` 只有质变函数一个读者（`0x0042015C`）；`0x004CB6BA` 有两个读者。
- **质变管理器不得写入 `0x4CB6BA`**。需要改后缀显示时，应使用 data管理器 的特效页，并明确它会同时改变 ×1.5 行为。

## 一、质变函数调用链

入口 `0x004200F5`（6.6）：

```asm
004200F5  55                 push ebp
004200F6  8B EC              mov ebp, esp
004200F8  0F B6 D2           movzx edx, dl          ; 等级
004200FB  0F B6 08           movzx ecx, byte [eax]  ; 初始特效值
004200FE  0F B6 40 FE        movzx eax, byte [eax-2]; 特效号
...
00420145  2C 1A              sub al, 0x1A
00420147  80 B8 BA B6 4C 00 07  cmp byte [eax+0x4CB6BA], 7
0042014E  73 05              jae 0x00420155        ; ≥7 跳过 ×3/2
00420150  6B C9 03           imul ecx, ecx, 3
00420153  D1 E9              shr ecx, 1            ; ×3/2
00420155  80 FA 12           cmp dl, 0x12
00420158  72 0A              jb 0x00420164
0042015A  8A 80 CA B5 4C 00  mov al, byte [eax+0x4CB5CA] ; 覆盖表
00420160  3C FE              cmp al, 0xFE
00420162  75 02              jne 0x00420166
00420164  8B C1              mov eax, ecx
00420166  5D                 pop ebp
00420167  C3                 ret
```

直接调用点（6.6 标准基底）共 5 处：

| 调用点 | 调用后用途 | 是否依赖 EAX 之外的寄存器 |
| --- | --- | --- |
| `0x00407B46` | 结果送入 `0x407B9E` 合并累计值 | 否，只用 EAX |
| `0x00407CBF` | `add [ebp-0xC], eax` | 否，只用 EAX |
| `0x00461EAF` | `add [ebp-4], eax` | 否，只用 EAX |
| `0x00462196` | `mov [ebp-4], eax`，随后进入后缀/说明分派 | 否，只用 EAX |
| `0x00465EBC` | `add [ebp-4], eax` | 否，只用 EAX |

契约：

- 返回值为 EAX；ECX 在规则路径中同时为规则值。
- 原函数入口执行 `movzx edx,dl`；规则蹦床在开头也执行 `0F B6 D2`，保持 EDX 零扩展状态。
- 规则路径不执行 `push ebp`，也直接 `ret`，因此 EBP/ESP 平衡；EBX/ESI/EDI 不触碰。
- 原函数没有内存写入或函数调用，只有纯计算和表读取，所以提前返回不会遗漏副作用。

## 二、装备后缀格式化调用链

格式化函数入口 `0x0046215B`，实际函数体从 `0x00462167` 开始（前面是指令对齐 NOP）。关键片段：

```asm
004621B7  8B 45 F4                    mov eax, [ebp-0xC]          ; 特效号
004621BA  0F B6 88 BA B6 4C 00        movzx ecx, byte [eax+0x4CB6BA] ; 后缀类型
004621C1  83 7D 0C 00                 cmp dword [ebp+0xC], 0
004621C5  74 6F                       je 0x00462236
004621C7  91                          xchg ecx, eax               ; al=后缀类型
004621C8  3C 00                       cmp al, 0
...
004621DB  68 AC E6 48 00              push 0x48E6AC               ; "--"
...
0046223F  48                          dec eax
00462240  8B 0C 85 74 22 46 00        mov ecx, [eax*4+0x462274]   ; 数值格式串表
...
0046224F  E8 BC E2 FF FF              call 0x00460510             ; 名称/掩码/范围解析
```

后缀类型与显示：

| 类型值 | 显示 | 说明 |
| ---: | --- | --- |
| `0x00` | `--` | 无数值后缀 |
| `0x01` | `+N` | 值为 255 时显示“杀” |
| `0x02` | `+N%` | 带正号百分比 |
| `0x03` | `-N%` | 带负号百分比 |
| `0x04` | `N%` | 百分比 |
| `0x05` | `N` | 纯数值 |
| `0x06` | `N次` | 次数 |
| `0x07` | 策略名 | `0x00484002` |
| `0x08` | 属性名 | `0x00486ADB`，每项 5 字节 |
| `0x09` | 五属性组合 | `0x00423D45` |
| `0x0A` | 位掩码 0x3F | `0x00460565` |
| `0x0B` | 位掩码 0x1F | `0x0046056F` |
| `0x0C` | 范围/形状名 | `0x0040620A` 指针表 |
| `0x0D` | 阵型/范围名 | `0x0041AEB0` |
| `0x0E` | 地形名 | `0x0048C470` |
| `0x0F` | 攻击/策略/ALL | `0x0041AFCB`（6.6xKF 补丁） |
| `0x10` | 攻击/策略/ALL（补丁扩展） | `0x00460517` 分支 |
| `0x11`、`0x13` | 名称解析（补丁扩展） | `0x0046052C`、`0x00460540` |

调用点：

| 调用点 | 用途 |
| --- | --- |
| `0x00405CAE` | 把后缀文本写入界面缓冲区；无格式串时用 `0x48E68C` |
| `0x0046736C`、`0x004673C9` | 取格式化结果参与数值比较/差值 |
| `0x004621A6` | 物品查找失败时的内部回退 |

## 三、覆盖表的消费者

- 6.6 覆盖表 `0x004CB5CA`：唯一立即数引用 `0x0042015C`（质变函数）。
- 6.4/6.5 覆盖表 `0x0046236F`：唯一立即数引用 `0x0042017C`（质变函数）。
- 覆盖表只影响质变结果，不参与装备后缀显示；但 `0xFE` 表示“不覆盖”，预览和实际值都会沿用前一步计算结果。

## 四、事故复盘（1.2026.1111.2）

- 用户修改版与备份对比：全文件仅 17 字节不同，全部在覆盖表 `0x9D7CA` 与后缀表 `0x9D8BA`；入口仍为 `55 8B EC...`，无 `TMR1`。
- 旧版把后缀表当“自动/强制/跳过 ×1.5”开关，写入 `0` 或 `7`。
- 结果：16 个特效、21 件武器/防具的后缀显示被改；多数从 `+N%`/`N%`/`N次` 变成 `--`，`0x31/0x33` 从攻击/范围名变成策略名。
- 数值侧：`0x02/0x04/0x06 → 0x00` 仍在 `<7` 分支，`×3/2` 行为不变；`0x0C/0x10 → 0x07` 仍在 `≥7` 分支，跳过行为不变；只有 0x51 的覆盖值 `0x04→0x06` 是真实数值变化。

## 五、工具硬约束（1.2026.1111.4 / 1.5 / 1.6 起）

1. `SlotEdit` 不再包含 `Extra` 字段，代码层面没有写后缀表的入口。
2. `Apply` 写入前做白名单校验，只允许：
   - 安装/清理规则时的入口 5 字节蹦床与代码洞规则块；
   - 显式修改且值不同的覆盖表单字节。
   纯覆盖值写入不允许入口/代码洞变化；任何其他字节差异都会取消写入并报告偏移。
3. `--roundtrip` 增加全文件差异断言：
   - 写入后只有入口/代码洞/覆盖值变化；
   - 清理后只有覆盖值变化；
   - 纯覆盖值写入只改覆盖值字节；
   - 后缀类型表与未编辑槽位覆盖值保持不变。
4. `--verify` 对 6.6 检查 `0x4CB6BA` 的立即数引用数为 2（质变门控 + 后缀格式化）；数量异常说明布局变化，需要重新分析。
5. 代码洞选择除跳转目标外，还排除被 4 字节绝对地址/数据指针引用的区域。
6. 加载已安装规则的基底时，如果入口 E9 指向的旧代码洞仍被绝对指针引用，直接只读，要求从 `Ekd5.exe.bak-transform-*` 恢复；不再沿旧洞继续写。

### 5.1 6.6 代码洞风险复核

- 旧版选中的 `0x457D7B`（5618 字节）并非纯填充：文件内有 3 个绝对指针 `0x458A00`、`0x458B1F`、`0x458900` 落在该区间内，说明它被数据/跳转表引用。旧版只检查分支目标，存在覆盖数据表的风险。
- 1.4 起同时扫描所有 4 字节绝对地址；该候选被拒绝。
- 6.6 当前选中的新代码洞为 `0x4303DC`（4455 字节），无分支目标、无绝对地址引用。
- 6.4/6.5 的 `0x43060E`（3830B）与 18州 `0x43064A`（3770B）仍通过检查。

### 5.2 已安装旧洞的迁移保护

- 用 1.3 在 6.6 副本上安装规则（旧洞 `0x457D7B`），再用 1.5 `--verify` 加载该副本：
  `PASS 未知变体只读 已安装规则的代码洞位于被数据引用的区域；请从 Ekd5.exe.bak-transform-* 恢复原文件后再重新写入。`
- 1.5 不会接管旧洞继续写，避免把已损坏区域进一步扩大。
- 纯覆盖值写入回归：入口、代码洞、后缀表均不变，只有目标覆盖值字节变化。

### 5.3 规则合并与多槽写入（1.6）

- `Apply` 采用合并语义：未在本次编辑出现的槽位保留既有规则；`Stages=null` 不动规则；空列表只清除该槽位规则。
- UI 对“仅覆盖值变化”的槽位传 `Stages=null`，不再无谓重写入口/代码洞。
- 真实基底矩阵：26 个含 Ekd5.exe 的目录中 18 个可编辑；18/18 单槽往返 + 18/18 多槽往返全部 PASS。
- 多槽回归覆盖：多槽写入、重复写入只改 A 保留 B、单槽清理 B 保留 A、单槽清理 A 后入口/代码洞恢复、多槽纯覆盖值只改授权字节。
- 旧版迁移：1.3 的 6.6 旧洞只读；1.3 的 6.5/6.4 补丁可正常重新写入和清理。

## 七、与个人/兵种特效名称槽的区别

- 本文的 `0x4CB6BA` 是**装备特效**后缀类型。
- [特效后缀名-三基底存储格式](特效后缀名-三基底存储格式.md) 描述的 `0x4CC600`/`0x4FF560` 16 字节名称槽、`+0x0F` 尾部代码和选择器 `0x428346`，属于**个人/兵种特效名称**体系。
- 两套体系的地址、消费者和写入规则不同，不能互相套用。
