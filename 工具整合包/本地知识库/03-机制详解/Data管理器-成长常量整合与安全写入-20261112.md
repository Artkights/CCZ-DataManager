# Data 管理器成长与常量整合（2026-11-12）

Data 管理器 1.2026.1112.1 将宝物质变和全局档位迁入主工作区。规范源码位于 `data管理器/src`，两个独立工具和主程序共同引用纯 net8.0 的 `EngineGrowth.Core`。

质变规则仍按最高已达等级门槛取绝对值，未命中时回原生逻辑。主界面只提供等级/特效值规则，不覆盖独立的原生单值和后缀。档位只提供档位、阈值和最多 2 个 GBK 字节的显示文字，2～12 档；6.5 掩码及 6.6 原有修正调用保留。

TMR1 与 TIER1 使用有界且互不重叠的代码洞所有权。旧版整洞占有仅在原生函数、标记、代码可验证重建时收紧或重新布局；不可识别残留保留，容量不足拒绝写入。清空质变只能恢复其自有实际占用段。新增/缩短/清空后的精确 EXE 往返、两补丁共存及扩展 256/511 宝物引用已纳入回归。

原 88 个常量定义增至 174 个。普通数值独立于基址、字段偏移和运行期地址，按逻辑定义去重，并校验版本签名和同步站点。新增目录及候选审核文件保存在 `data管理器/config/engine-constants-*.json` 和 `engine-constant-candidate-resolutions.json`。133 条 JSON 候选逐项得到具体常量 ID 或只读理由，未决为 0；不要把 3518 个研究叶子当成新增可写常量。

6.6 `0x4CB6C0` 门控与 `0x4CB6BA` 后缀共享字节不独立开放；`0x4D1A80` 40×40/41×41 语义冲突不产生重复通用常量；`0x507EC0` 是可变长分组修正结构，当前仅验证 7 个空组、16 字节并只读展示，非空样本和扩容写入契约尚未确立。

写入通过主工作区事务合并表格、引擎、质变、档位和常量候选，先检查重叠与源 SHA，备份后写入并复读，失败恢复文件和草稿。详细来源、限制和验收见 `data管理器/文档/常量迁移与知识对账.md`、`共享成长核心-质变与档位.md`、`四项整合验收报告-1.2026.1112.1.md`。
