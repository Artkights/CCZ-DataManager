# 布局与读取性能优化说明及验收记录

发布目标：`1.2026.1113.1`，对照正式版：`1.2026.1112.3`。若目标版本已占用，以最终运行程序、Git 标签、Release 和构建记录中的修订号为准。

三基底各三次候选运行及对应旧版的正式性能对照、三基底各 100 轮自然切页，以及最终 26 项专项回归均已通过。本文记录实现、使用方法、实测结果和验收边界；最终发布 EXE 的三基底检查、源码包五工程独立构建、源码提交及交付哈希由运行包中的 `构建与源码包记录.json`、`验证记录.json` 和 `SHA256SUMS.txt` 关联，原始证据收录于 `验收证据`。

## 使用变化

设置区与筛选区仍分为两层，窗口变宽后编辑控件会利用新增宽度。设置行中的版本、布局、快速定位和表选择按最小可用宽度及 20／25／25／30 的剩余宽度权重展开，“隐藏空白行”保留自然宽度。隐藏快速定位或表选择时，其位置一并退出排布。

筛选行的三组“属性＋关键词”在同一行中等宽展开。每组属性框与关键词框按约 40%／60% 分配，逻辑最小宽度为 112 DIP／128 DIP，同时考虑字体测量结果。窗口较窄时先将“查询、清空、匹配数量”完整移至下一行，再按三列、两列、一列整组换行；不足一行的条件组平分其所在行的可用宽度。操作尾组保持自然宽度并靠右。

保存、撤回、导入、导出等命令按钮仍按内容采用自然宽度。改变窗口尺寸、字体、DPI 和控件可见性时，布局调度器合并后续排布；子控件保留稳定父级，仅在边界发生变化时写入尺寸。

查询操作沿用三组属性筛选规则：

1. 属性留空表示当前详情子页的“全部属性”；关键词留空的组不参与筛选。
2. 在同一输入框用空格分词，框内各词和三个有效条件组均须满足。连续空格、全角空格及首尾空白统一处理。
3. 输入、修改属性不会立即改变结果。点击“查询”或在任意关键词框按回车，一次应用三组条件。
4. 点击“清空”重置当前子页并立即恢复范围内记录；隐藏空白行和已有外部表格过滤继续参与最终结果。
5. 匹配采用忽略英文大小写的字面包含，数字按文本处理。快速定位继续用于精确跳到真实记录 ID。

例如第一组选择“ID：名称”并输入 `1`，第二组选择“R形象编号”并输入 `2`，结果须同时满足这两组。`2` 可以匹配 `12` 或 `20`；同框输入 `曹 操` 时，两个词都须命中。空白属性范围内的不同词可以命中同一实体在当前子页的不同属性。

各详情子页分别记住输入、属性和已应用条件，重新打开项目后重置。查询读取当前草稿；执行前继续验证并提交未失焦编辑。验证失败保留编辑内容、用户输入和旧结果。大查询进行期间产生的新编辑也会阻止结果覆盖当前详情，完成编辑后可重新查询。

CSV 继续沿用格式导入版的开放规则：Profile、Variant、布局修订、schema 和 TableKey 来源信息均为可选提示；导入按目标可写字段的实际格式、编码和物理容量判断，只读及保留列跳过。具体规则见《CSV格式导入说明与验收-1.2026.1112.2》。本次没有变更 CSV、XLSX 或游戏文件协议。

## 读取与查询实现

左栏导航与属性查询使用不同的数据层。导航缓存保存真实 ID、名称和显示标签；三个查询关键词均为空时，直接读取导航记录，不物化当前子页的其他业务属性。

指定属性查询按实际使用的属性集合建立快照，重复条件共享同一列。“全部属性”仅在执行有效查询时读取完整子页。属性描述、导航及名称目录、属性值缓存分别复用，匹配复用分词结果并在某一必要条件不成立时提前结束该条记录。

大范围属性捕获分批在工作区所属 UI 线程读取，后台线程只匹配已完成的不可变快照，不访问 WinForms 控件或活动 DataTable。切页、清空及执行新查询会取消旧任务；结果发布前再次核对上下文、查询代际、数据修订及待编辑状态，防止迟到结果覆盖新页面或未完成编辑。

业务目录共享 ID 到行、ID 到名称、物品分类、装备候选、效果名称、类型与范围名称等读取结果。引用和枚举查询同时保留原始编号和当前显示名称。人物台词映射按真实实体及依赖复用，策略学习批量建立关联，兵种矩阵、装备许可及扩展宝物继续使用现有业务映射，不按无关物理表的相同编号直接拼接。

缓存依赖记录文档身份、结构与字段修订。ID 或结构变化重建相关行目录；名称变化刷新依赖名称的目录；其他属性变更只使相应依赖失效，未知变更保守刷新对应文档。打开、重载、导入、编辑、撤回重做、保存及字段增删均进入失效流程。项目关闭或替换时，释放原会话缓存和文档订阅。

页面激活按“验证并提交编辑、切换上下文、配置必要结构、合并查询与既有过滤、恢复真实 ID、按需绑定详情”推进，合并物理表列表与快速定位刷新，消除拓展分类进入时重复绑定。可复用的业务页宿主保留，详情复用分别检查结构版本和真实数据依赖。

导航复用稳定的 identity 条目对象，记录身份和显示文字未变化时不反复创建同一批选项；文字测宽结果随相应显示内容与字体条件复用，减少切页时下拉列表原生测量和排布工作。物理表进入时合并导航、查询与空白行过滤的绑定，避免同一次切换重复刷新列表及详情。

## 源文件与预览

一次打开或重载使用源文件读取会话，按解析后的完整路径复用字节、SHA256 和基础读取结果。版本检测、扫描和各物理表读取复用同一次操作中的源快照；各表的范围、布局及字段检查仍独立执行，字段与 DataColumn 对应关系预先计算。

根目录与 `E5` 子目录中的同名文件按实际路径区分。打开时的哈希只属于该读取会话，保存前重新检查当前磁盘文件，继续执行外部修改冲突检测。

资源目录使用变更通知和合并检查复用已完成目录，减少单次切页重复扫描。调色板及其候选路径也参与失效，包括根目录、`E5` 与 fallback 调色板的创建、删除和内容变化。离开预览页会停止动画、取消未完成请求；返回时可复用仍在共享预算内且代际有效的小图。请求取消、迟到回调隔离及图像租约回收继续生效。

范围预览启用双缓冲，父页与子预览对相同状态采用幂等更新；未变化的数据和选中状态不重复绑定或触发重绘，减少切换范围分类及返回页面时的重复绘制。

## 缓存预算与内存解释

| 项目 | 当前配置 | 含义 |
| --- | --- | --- |
| 工作区数据读取缓存 | 256 MiB | 导航、文本、行目录、业务目录和属性列等可计量常驻项共用预算，按需创建并按最近使用淘汰 |
| E5 归档缓存 | 约 128 MiB | 维持现有共享归档预算，提高已读取内容复用率 |
| 解码像素缓存 | 约 96 MiB | 维持现有共享像素预算，按需解码，不全量预载项目图片 |
| 常规基底进程专用内存 | 约 1 GiB 软目标 | 独立观察预热后自然运行平台期，打开、导入和首次索引允许短暂升高 |

缓存预算是相应缓存项的估算上限，不等于整个进程内存上限。工作区 DataTable、源字节、控件与原生句柄、正在捕获的快照和仍被使用的图像等会另占内存；正在执行的操作也可能短暂保留已从常驻缓存淘汰的对象。实现不在正常操作路径强制 GC，以冷缓存淘汰及会话释放管理长期占用。九次候选 30 轮和三基底各 100 轮自然运行的专用内存均低于 1 GiB，详见下表；旧工作区回收另有测试专用强制 GC 诊断，两者不混用。

## 正式性能验收方法

正式对照使用冻结的 `1.2026.1112.3` 与候选版，在同一机器、实际 DPI、窗口尺寸和测试流程下串行运行。修正后的测试先设定要进入的业务或物理视图，再触发唯一的真实导航事件，避免额外调用 smoke 导航造成重复激活。两侧采用同一流程。

样本为 6.4 洗隋、6.5 加强版未加密、6.6 复刻版山贼的原始文件临时副本。每个版本、每个基底三次独立运行，共 18 次，每次预热后执行 30 轮。正式报告的实际 DPI 均为 144，窗口均为 1280×800。每个场景合并三次运行的 90 条原始 `Samples`，按 nearest-rank 统计 P50、P95 与最大值，不平均三次 P95。

原始 JSON 已通过 `FirstEntries` 独立保留逐场景首次进入的 `SelectMs` 和 `ReadyMs`；九份候选报告各含 16 项首次进入记录。`FirstEntries` 不混入预热后的 `Samples`，也不作为热切换的额外样本。冷启动使用 `ColdInteractiveMs`，首次全局可见图片使用 `FirstVisibleImageMs`，逐页图片完成时间未纳入本次热切换门槛。

| 验收项 | 要求 | 正式结果 |
| --- | --- | --- |
| 常用业务页及物理表热切换 | P95 ≤200 ms | 33 个基底/场景组合全部通过，新版最高 P95 为 148.07 ms |
| 基线超过 200 ms 的慢场景 | 同时达到对应门槛，且 P95 至少改善 40% | 16 个慢场景全部通过，P95 改善 45.30%～70.17% |
| 每次候选运行 UI 心跳排队延迟 | P95 ≤100 ms | 九次全部通过，分别为 60.39～89.07 ms；逐次值见下表 |
| 打开项目至可操作 | 三次独立运行中位数相对基线退化 ≤10% | 三基底全部通过，中位数缩短 42.46%～45.32% |
| 资源、范围、公式热切换 | 相对基线退化 ≤10%；旧慢场景至少改善 40% | 15 个组合全部通过；最差退化 1.14%，最大改善 64.02% |
| 常规基底自然运行专用内存 | 约 1 GiB 软目标，内存结论单列 | 九次第 5..30 轮峰值均通过，最高 484.72 MiB；100 轮结论另验 |
| 100 轮切页与反复开关项目 | 平台期、句柄与旧工作区回收独立记录 | 三基底各 100 轮已完成，峰值均低于软目标，句柄稳定；独立项目回收结论见生命周期记录 |
| 功能与布局 | 对应专项回归通过 | 最终 26／26 项通过，源码和测试运行文件前后哈希不变；九种窗口／字体组合通过 |
| 最终 EXE 与源码独立构建 | 发布前执行三基底与五工程检查 | 逐项结论由同版运行包内构建与验证记录关联；缺样本限制单列，不等同于全部动画已通过 |

九份候选报告的 `NavigationOnlyCache.MaterializedColumns` 与 `MaterializedValues` 均为 0。三次运行中源文件读取及哈希次数分别稳定为：6.4 为 4／4、6.5 为 4／4、6.6 为 5／5；同一路径的源快照在会话中复用。目录构建、缓存命中、属性物化、绑定及布局计数用于解释算法变化。图片完成时间单列，不以延迟加载代替读取完成计量。自然运行数据与测试专用强制 GC 回收数据分开记录。

`tools/Compare-RuntimePerformance.ps1` 只接收 `baseline-final-{基底}-{1..3}` 与 `candidate-final-{基底}-{1..3}` 的正式 `runtime-performance.json`，检查样本完整性、版本一致性、来源、实际 DPI、窗口和流程声明，输出 `performance-comparison.json` 与 `.md`。缺失、无效或不一致证据会阻止通过。诊断烟测及候选中间版数据不进入正式合并结果。

`tools/Verify-RuntimeOptimization.ps1` 顺序运行查询缓存、三基底源读取与查询核心、业务映射、完整查询 UI、核心功能、CSV、异步查询管线、会话与项目生命周期、顶部布局、拓展分页、预览和资源等回归。该脚本的 `PerformanceTargetsCertified=false` 表示功能回归本身不能认证性能门槛；性能须另由正式对照与内存证据判断。

## 布局和样本边界

顶部专项布局矩阵覆盖 1100×650、1280×720、1920×1080，以及 100%／125%／150% 字体比例模拟，共九种组合。检查整行宽度利用、同行条件等宽、控件裁切和重叠、尾组靠右、隐藏占位移除、窗口加宽后输入框增长，以及稳定尺寸下布局行数不反复变化。

当前实际显示环境记录为 `DeviceDpi=144`，即 150% 显示器 DPI。字体比例模拟是在这一真实 DPI 下改变字体，不等同于真实 96 DPI／120 DPI 显示器或跨屏 DPI 切换。九种组合的正式候选截图、JSON 和执行结果收录于运行包的布局回归证据，宽窗口和窄窗口大字体截图另经目视检查；真实 100%／125% DPI 环境的未覆盖部分保留为限制。

某些原始基底缺少可选的拓展特效归档。性能对照保留原始文件集合，不向缺失基底补造文件。异步查询管线集成测试单独在可丢弃副本中构造符合当前 Profile 声明几何及 codec 的 synthetic Effect 归档，用于覆盖宽表、大查询取消、导航与清空、迟到结果隔离和待编辑保护。日志以 `QUERY_PIPELINE_SYNTHETIC_EFFECT` 明确标记。

这类合成数据只证明所列算法与生命周期路径，不代表真实 Effect 归档的内容正确性、实际资源解码或原始基底的大归档性能。若实际文件存在但无法加载，测试直接失败，不以合成数据替代。基底原始文件不受修改。具体缺失基底、文件名、行数与字段规模，以正式日志和验证记录逐项填写。

Mcall 动画真实样本缺失时，取消、代际及所有权测试可提供生命周期证据，无法据此声称真实 Mcall 动画播放与全部帧解码已验收。静态图片、合成测试与真实动画样本的覆盖分别记录。此次管理器验证操作临时副本；未执行游戏内实战时，不将管理器读写回归解释为游戏内运行通过。
