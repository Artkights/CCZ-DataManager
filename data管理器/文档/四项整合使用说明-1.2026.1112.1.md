# 四项整合使用说明 · 1.2026.1112.1

本版把人物图片浏览、宝物质变、能力档位和新增引擎常量整合到同一个 Data 管理器。启动入口为 [`发布/1.2026.1112.1/data管理器.exe`](../发布/1.2026.1112.1/data管理器.exe)。程序面向 Windows x64，使用系统已安装的 .NET 8 Windows Desktop Runtime x64。

操作与验证结果分别见本文和[四项整合验收报告](四项整合验收报告-1.2026.1112.1.md)。新增常量的数量、来源、逐项归属和只读边界见[常量迁移与本地知识对账](常量迁移与知识对账.md)。历史版本保留在原目录，当前版本以窗口版本号和上述入口为准。

## 人物：头像、R 形象和 S 形象

人物页统一提供头像、R 形象编号、S 形象编号三列。每列包含编号下拉框、对应定位按钮和图片预览。头像列只显示头像。下拉候选保留编号文字，并显示当前项目中对应图片的缩略图。

在编号框中键入合法编号，预览会随输入更新；尚未完成的输入不会覆盖最后一张有效预览。缺少资源时保留输入的编号，并清空图片或显示不可预览状态。下拉缩略图按比例缩放，资源更新后会刷新缓存。

- **定位头像**：跳转到“图片设定”的头像条目，选中并高亮对应逻辑编号；编号 0 仍对应头像 0。
- **定位 R**：跳转到“图片设定”的 R 形象条目；前后方向使用同一个逻辑编号。
- **定位 S**：沿用现有 S 形象定位。需要区分转职阶段或默认兵种阵营时，会显示选择窗口，再定位三个动作文件对应的实际 Unit 图号。

定位会先校验并接收当前控件中的草稿。单纯浏览图片和恢复原编号不会改写游戏文件；更改图片指定后仍需保存项目。图片设定中的图片导入沿用即时保存行为。

窗口较宽时，人物基本字段和三列图片并排显示；可用宽度不足时，三列图片移到基本字段上方，页面纵向滚动。定位按钮和编号框随字体调整所需高度。

## 引擎扫描：质变设定

打开“引擎扫描 → 质变设定”，从左侧宝物特效列表选择特效号。列表继续显示原有 `0xNN 名称 N件` 格式，并支持编号查询。只列出有武器/防具引用、已有规则或正在编辑规则的特效号。

右侧上半部分为“等级规则”，下半部分为“引用装备”，两块均分可用高度。等级预览和冗长说明已移除；“新增”“删除”随规则表显示。引用装备按所选特效号列出当前项目 0～511 范围内的武器/防具，并反映未保存的装备名称和特效草稿。

等级规则每行填写“等级”和“特效值”。等级范围为 1～99，特效值范围为 0～255，同一特效号不能有重复等级，最多 8 条规则。使用“新增”添加规则，选中一行后用“删除”移除；直接编辑单元格可修改现有规则。当前等级达到门槛时，使用最高符合门槛那一行的绝对特效值；低于首个门槛时继续使用原生公式，清空全部规则后恢复原生行为。

能否编辑由当前引擎布局和代码洞校验决定。无法安全使用等级规则的项目会显示只读原因，避免按其他基底的地址写入。原有 6.6 后缀与门控表的边界继续保留。

## 兵种：档位设定

打开兵种页，右侧下方区域由上下两块平分：上方是原有策略学习，下方是“档位设定（全局）”。档位设定影响当前项目的全局五维档位，切换兵种不会建立独立的档位表。

表格仅保留“档位”“阈值”“显示”三列。档位序号自动维护，第一行是没有阈值的基准档。后续行的阈值使用 0～255 的整数，并且必须严格递增。可直接修改阈值和显示文字，也可用“新增”“删除”调整档数；基准档不可删除。档数范围为 2～12 档。

“显示最多2字节”提示保留在按钮旁，按 GBK 编码计算。显示文字应占 1～2 个 GBK 字节，例如 `AB` 或一个可用汉字；两个汉字、emoji、超过长度或无法编码的文字会被拒绝。

## 常量编辑与统一保存

“引擎扫描 → 常量编辑”现包含 174 个逻辑常量定义，比原有 88 个新增 86 个。新增项涵盖成长与转职、经验公式、原生质变门槛、金钱费用、能力上限、命中与策略修正、策略 AI 评分，以及经过验证的内嵌参数表。一个逻辑定义可能同步修改多个已确认的关联指令操作数。

搜索并选中常量后，输入新值并点击“应用到草稿”；最后使用项目保存或 Ctrl+S 统一写入。质变规则、档位阈值、显示文字和档位封顶在常量页提供“打开设定”入口，编辑仍使用同一份项目草稿。

常量只在适用基底且签名/上下文校验通过时开放写入。除数、字节参数和枚举等按各自范围验证。研究资料中的地址、结构偏移、运行期变量和存在冲突的站点保留只读；逐项原因见[知识对账说明](常量迁移与知识对账.md)。

Data 表格、质变、档位和常量的修改合并进入现有保存事务。保存前校验候选及冲突，写前备份，写后复读；发生错误时回滚。已有撤回、重做、未保存提示和项目切换流程继续参与这些草稿的生命周期。游戏运行、外部文件 SHA-256 变化或无法证明安全的旧代码洞会阻止保存，并保留草稿供处理。

质变与档位共享核心的设计、迁移和边界见[共享成长核心说明](共享成长核心-质变与档位.md)。

## 源码与验证入口

主程序源码入口为 `src/DataManager.App`。`src/EngineGrowth.Core` 为质变和档位共用的编译、扫描和协调层；`src/TransformManager.App`、`src/TierManager.App` 保留独立程序入口。图片控件与编解码依赖同级 `../形象管理器`，复制源码时须一并保留。

`tools/Build-ReleasePackage.ps1` 生成程序和带 SHA-256 清单的源码包，并在独立解压目录构建 Data 管理器、两个独立管理器及相关测试项目。`tools/Sync-GitHubSources.ps1` 按同一源码清单同步到干净的 GitHub 检出；脚本本身不提交或推送。常量目录和知识对账文件引用的 CSV/JSON/Markdown 证据快照随源码包保留，正常构建无需重新运行知识库生成器。

人物图片集成测试由测试宿主运行，覆盖 1100×650、1280×720、1920×1080 三种实际窗口像素尺寸和 100%、125%、150% 三档字体；三个基底的“人物布局元数据.json”逐张记录窗口、客户区、字体和 `DeviceDpi`。本轮测试宿主实际为 **144 DPI**，三档字体分别为 9、11.25、13.5 pt；100%/125%/150% 标签表示字体倍率。发布 EXE 的质变、档位和常量界面另行通过内置离屏验收，四个基底报告中的实际 `DeviceDpi` 也均为 **144**。验收期间未调整操作系统缩放，未覆盖 120 DPI 或跨显示器切换。具体测试、截图和适用范围以[验收报告](四项整合验收报告-1.2026.1112.1.md)为准。
