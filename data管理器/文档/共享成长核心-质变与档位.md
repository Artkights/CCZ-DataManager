# 共享成长核心：质变与档位

日期：2026-11-12。

## 实现结构

`src/EngineGrowth.Core` 为纯 `net8.0` 类库，仅依赖 Iced。它包含质变与档位的 PE 读写、静态扫描、模型、TMR1/TIER1 元数据、规则编译、纯内存候选生成和代码洞分配。为兼容原有调用代码，迁出的类型保留 `TransformManager.App` 与 `TierManager.App` 命名空间；类型现在由共享程序集提供。

`TransformManager.App` 和 `TierManager.App` 改为引用共享类库。独立 UI 与 CLI 保留，直接写盘仍由各自原有备份/暂存/复读事务包装负责。主 data 管理器不调用这些独立写盘入口。

`DataManager.Core/Domain/EngineGrowthDraftService.cs` 是主工作区适配层。`For(workspace)` 获取整份工作区唯一全局草稿并注册 `IWorkspaceDraftParticipant`；`SetRules`、`SetTiers` 提交有效单元格或增删操作，深复制前后快照并显式加入 `DelegateEditCommand`，因此草稿撤回/重做与普通数据编辑共用命令栈。`Changed` 通知 UI 重绑。专用草稿接口并不会自动提供撤回；显式压入命令是必需实现。

`PreparePlan()` 生成带整文件基线、候选和复读验证器的 `GrowthPatchPlan`；`PrepareBinaryEdits()` 将真实差异转换成工作区有界补丁。统一保存按 SHA-256 拒绝外部修改，并在候选验证失败时保留原文件及草稿。保存历史恢复后，主 UI 需调用 `Reload(true)` 重新读取扫描结果及草稿基线。

## 界面数据语义

质变左栏沿用独立工具的特效号枚举方式：`0xNN 名称（N 件）`，只列出有效质变表范围内存在武器/防具引用，或已有规则/尚在编辑的特效号。没有引用的旧规则仍可进入清理。主工作区适配直接遍历 `items-low`、`items-high`、`items-extended`，用 `ItemSemanticResolver` 解析当前草稿的真实特效号、名称和类别，因此包含现有 0..511 宝物；辅助装备及消耗品不混入质变引用。引用按宝物 ID 去重和排序。

等级规则采用门槛语义：当前装备等级达到某条规则后，使用最高符合等级规则的值，直到下一条门槛；低于首条门槛沿用原生公式。每特效最多 8 条，等级 1..99，值 0..255，重复等级拒绝。删除该号全部规则回退原生行为；未编辑特效号规则保持原样。6.6 的后缀/成长门控表不进入质变写白名单。

档位是 EXE 全局五维属性档位，切换兵种不创建单独副本。允许 2..12 档；首行无阈值且不可删除，其他阈值为 0..255 严格递增。显示不能为空，最多 2 个 GBK 字节，拒绝不可编码字符及空字符：`AB`、`中` 有效，`ABC`、`中文`、emoji 无效。既有 6.5 强化成长掩码和 6.6 修正/辅助调用保留。

## 同一候选中的代码洞所有权

原两个独立工具都选择最大的未引用填充区，并把整段长度写入 marker。若将另一种补丁安装在原洞尾部，后续删除质变规则可能擦除档位。因此本实现统一分配：新装质变按编译所需长度向 256 字节对齐、最少 1024 字节；档位预留 1024 字节。分配器排除已占用范围、分支目标及 PE 中的绝对地址引用，最终同时验证两份 marker 所有权不重叠。

既有 TMR1/TIER1 的整洞所有权先保持有效，不能直接借用尾部。若当前代码能从 marker 完整重建，其他内容均为填充，则先在内存恢复原入口、调用点及显示指针，确认没有未知外部引用，再释放旧洞并重新编译到有界区域。两个旧 marker 声称整洞重叠时，只在实际已用代码块互不重叠、均可重建时执行同样迁移。

主工作区对“旧 TMR1 整洞与尾部 TIER1 重叠”执行同样的只读预检：只有旧洞引用全部来自可完整重建的管理区域或已知调用点，且完整候选复读后与既有规则、阈值和显示等价，才允许直接编辑质变。预检不写文件、不产生草稿；管理区外未知绝对引用继续保持只读并拒绝协调写入。

早期档位写入会留下旧版本表/字符串/元数据残余。发现这些非填充内容时，不擦除也不挪动它们：保留原位置及全部残余字节，只把该 owner 的长度收紧到包含所有残余的对齐边界，释放证明为填充的尾部；另一补丁分配独立区域。扩写新规则/档位若会触及保留的旧残余，会将该活动补丁迁到另一个独立安全区；旧残余保持原字节，旧档位 marker 仅清除识别头以避免重复识别。清除质变也仅恢复自身已验证代码区，保留旧残余。若收紧后实际仍有重叠、空间不足、代码被未知修改或引用不能证明安全，则拒绝整次写入。

本地 6.5 基底的旧 TIER1 另有已知历史 CALL 编码缺陷：生成 rel32 时漏减 CodeVa。兼容器仅接受能逐字节重建、且差异恰好是已知 mask/correction/helper 调用的四字节位移等于“正确 rel32 + CodeVa”的旧格式；旧版未使用显示索引的零指针也可识别。迁移用当前正确编译器生成调用。任何其他代码差异都拒绝，不以宽松签名覆盖未知补丁。

质变规则改短时，先恢复可重建的旧实际占用段，再写新规则，避免自身旧元数据被误当作需要保留的外部尾部；其他未知字节仍保持。清除时按 TMR1 记录的原填充值恢复自己的实际占用段，未用填充尾部保持原字节。三基底新增、缩短、清空规则后与规范化基线的整个 EXE 逐字节一致。

## 验证

独立测试项目：`src/EngineGrowth.Core.Tests`。构建：

```powershell
dotnet build data管理器/src/EngineGrowth.Core.Tests/EngineGrowth.Core.Tests.csproj -c Release
```

在仓库根运行：

```powershell
& 'data管理器/src/EngineGrowth.Core.Tests/bin/Release/net8.0/EngineGrowth.Core.Tests.exe' '基底/洗隋' '基底/加强版6.5未加密版' '基底/复刻版6.6山贼'
```

测试纯候选在内存处理三个基底，验证源文件未改；真正保存、历史和失败场景仅在测试输出目录的副本运行，结束后删除自己的副本。覆盖：

- 三基底同时安装、重复改写、重开回读、清除质变保留档位、档位改写保留质变。
- 规则门槛区间、重复等级拒绝，2 档及 12 档编译/回读，GBK 字节限制和不可编码显示拒绝。
- TMR1 旧整洞迁移、旧质变/档位实际共存、未知尾部保留或拒绝，所有权无重叠。
- 旧 TMR1 全洞与尾部 TIER1 的工作区直接编辑、保存重开；管理区外未知绝对引用时拒绝且保留文件及草稿。
- 新增规则、缩短规则、清空规则后整个 EXE 精确还原规范化基线，没有旧代码、元数据或填充改色残留。
- 工作区脏状态、草稿撤回/重做、统一保存、已保存历史逐字节撤回/重做、失败保存保留原文件与草稿。
- 当前未保存宝物特效号改变后的引用刷新；真实 512 宝物表的 256/511 引用、去重、未保存末条名称/特效号刷新。

成功标识为三条 `SHARED_OK`、`LEGACY_WORKSPACE_OK`、`WORKSPACE_OK`、`EXTENDED_REFERENCES_OK` 及最终 `ENGINE_GROWTH_CORE_TESTS_OK`。测试不依赖主 WinForms 测试入口。

本次验证结果：三基底共享核心、工作区草稿/历史/失败恢复、真实 256/511 扩展引用全部通过；两个独立 App Release 构建通过；独立档位 CLI 三基底往返通过，独立质变 CLI 多槽增改清空与覆盖值往返通过。质变 CLI 在测试副本中先验证并规范化已有成长补丁，再进行严格质变白名单测试；旧补丁迁移本身由共享测试单独验证。
