# 三组属性筛选说明与验收

适用发布目标：`1.2026.1112.3`。若修订号已被占用，以最终 Release、运行程序版本和验证记录中的版本号为准。

## 使用方法

当前设置栏下方提供三组“属性下拉框＋关键词输入框”。三个属性和输入最初都为空；属性框的“全部属性”表示当前详情子页的完整记录内容。

1. 按需要在每组左侧选择属性，在该组右侧输入关键词。属性候选随详情子页变化，始终包含“ID：名称”。人物页还可选择“R形象编号”“S形象编号”“武力”“列传”等实际存在的属性。
2. 点击“查询”或在任一关键词框按回车，一次应用三组条件。输入或更换属性时，结果保持上一次查询状态。
3. 点击“清空”，重置当前子页的三组属性、关键词及已应用条件，并立即恢复结果。隐藏空白行及外部表格筛选继续生效。

需要直接跳到指定记录时，使用设置栏现有的“快速定位”。关键词框是普通文本输入。

| 组别 | 属性 | 关键词 | 含义 |
| --- | --- | --- | --- |
| 第一组 | ID：名称 | `1` | ID 或名称中包含字符 `1` |
| 第二组 | R形象编号 | `2` | 实际 R 形象编号的文字中包含 `2`，例如 12、20、22 |
| 第三组 | 空 | 空 | 不参与筛选 |

上述结果必须同时满足第一组和第二组。每框中的多个词也必须全部满足：在“ID：名称”框输入 `曹 操`，要求身份文本同时包含“曹”和“操”。普通空格、连续空格、全角空格和首尾空白统一处理。

属性留空时，同一框的多个词可以分别命中当前子页的不同属性。例如一词命中名称，另一词命中列传，仍可匹配同一人物。空关键词组不参与筛选，三组全空时恢复当前范围的记录。

匹配忽略英文大小写，采用字面包含。数字按文本处理；`2` 可以匹配 `12`、`20`。`[`、`]`、`*`、单引号等均按普通字符处理，未引入正则、通配符及数值比较语法。

## 查询范围和草稿

查询范围为当前详情子页的完整内容，不受滚动位置或内部翻页影响。引用及枚举属性同时支持当前显示名称和原始编号。台词、兵种矩阵、学习策略及装备许可按业务关联读取；同一编号的无关物理表不会自动拼接。现有“施展地形”“辅助分组”等独立全局配置子页只提供“ID：名称”。

“全部属性”包括与当前实体有关的字段、正文和关联名称，不包括按钮文字、诊断信息、原始保留字节及独立全局设置。没有实体属性的配置子页仅提供“ID：名称”。物理表模式只查询当前物理表实际展示的数据列和记录身份。

查询读取工作区当前草稿。执行前会验证并提交尚未失焦的编辑；验证失败时保留错误编辑、查询输入及原查询结果。导入、编辑、撤回、重做和保存后，已应用查询会使用新草稿重新计算。

每个详情子页分别记住尚未执行的输入和已应用条件，切回时恢复。重新打开项目会清空这些内存状态，不保存到配置文件。若基底失去某属性，相应条件会清除并提示；缺失属性不会被当作“全部属性”继续查询。

没有匹配时会显示空状态并停用详情编辑内容。筛选区、清空按钮和详情子页切换仍可使用。快速定位到筛选外的记录时，会清除当前查询以显示该记录。

## 验收入口和证据

以下是验证入口及检查项；实际执行结果以发布包中的验证记录和命令日志为准。本文不作为测试通过凭证。

| 入口 | 重点检查 |
| --- | --- |
| `RecordQueryServiceTests.Run` | 三组及多词 AND、Unicode 空白、跨属性、字面匹配、真实 ID、R/S、引用、跨段宝物、子页及物理表范围、文档替换和草稿撤回重做 |
| `--record-query-ui <基底目录>` | 用户示例、三组独立输入、回车/按钮执行、清空、子页记忆、零结果切页、未失焦编辑、错误保护、外部 RowFilter、隐藏空白行、快速定位、项目重开及物理表真实 ID |
| `--record-query-bindings <基底目录>` | 共享/特殊台词槽、转置矩阵、学习策略双向关联、跨低高扩展宝物业务语义、装备许可、缺可选字段及拓展数据末页完整范围 |
| `--ui-font-scale <基底目录> <输出目录>` | 100%/125%/150% 字体比例 × 1100×650/1280×720/1920×1080；三组控件完整性、边界、重叠和整组排列；生成截图及实际 DeviceDpi 记录 |
| 记录语义和核心回归 | 左栏记录身份、共享台词、转置矩阵、宝物编号及现有读写协议 |

字体比例验证使用真实显示器 DPI 加额外字体比例模拟，不等同于真正的 100%/125%/150% 显示器 DPI 切换；报告应分别记录真实 DPI 和模拟比例。缺少其他基底或真实 DPI 环境时，须在最终验证记录如实列为验收限制。

发布前还需完成运行包及完整源码包生成、源码包解压后的独立构建、最终 EXE 验收、使用说明和 SHA256 清单。具体版本、资产文件名及验收结论以最终 GitHub Release 为准。
