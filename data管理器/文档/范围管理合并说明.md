# Data 管理器与范围管理整合（1.2026.1110.2）

打开 Data 管理器中的项目后，在主页面选择“范围管理”，即可使用“攻击范围、穿透范围、拓展范围”三个子页。三个子页共同编辑当前项目，不需要再次选择基底目录。离开范围页会恢复 Data 管理器原有的目录布局。

## 范围候选与即时预览

兵种“穿透”和策略“穿透范围”现在共用当前项目实际存在的穿透范围目录，包含原生范围、已保存扩展和本次尚未保存的新增范围。新增范围后，可直接切到兵种或策略页面选择，不需要先保存范围或重新打开项目。攻击范围及施法范围也使用当前项目的对应攻击目录。

编号按实际定义显示，不按最大编号补齐。例如 6.6 新增穿透 12、13 后，不会自动补造原生目录中不存在的 11。原生特殊范围仍可选；基底表中已有的未知值及保留值继续保留，图片条目本身不代表已经定义了对应范围。界面的编号和名称显示方式沿用原样。

新增或修改范围的预览直接取当前草稿，修改同一编号的几何或中心后，下拉缩略图及输入栏旁边的图片同步更新。恢复、撤回、前进、保存历史恢复和项目切换也会刷新目录与预览，刷新时保留正在输入的数字和光标。

新增范围定义与兵种、策略字段引用可以一次保存。范围校验未通过时，保存会保留具体编号和原始原因，并跳到对应范围项以便修正；不会丢弃普通字段或范围草稿。穿透最多 24 个额外坐标等原有规则继续适用。

## 操作与保存

- 范围目录、编号与名称显示沿用独立范围程序；生成元、中心、图片预览、新增、删除、恢复和拓展映射操作沿用原组件。
- 范围修改先形成草稿。顶部“撤回”“前进”和对应快捷键共用 Data 管理器的草稿时间线，普通字段与范围操作可以交错撤回。文本框内部的撤销仍沿用原行为。
- 点击顶部“保存”时，普通 Data 字段、EXE 字段、范围定义和对应的 Hitarea.e5 / Effarea.e5 候选统一提交。备份、历史记录、写后复读和失败回滚由 Data 管理器现有事务负责。
- “历史撤回”“历史前进”按整次保存恢复文件，并重新读取范围预览。打开、切换、重新扫描或退出项目时，范围草稿纳入未保存提示。
- 不合法的生成元保留为错误草稿，保存会显示错误；可以继续修正、撤回或放弃。普通字段与范围重建相互覆盖、资源被外部修改或文件写入失败时，不提交部分结果，保留可继续处理的草稿。

## 6.6 索引图的颜色处理

6.6 的 Hitarea.e5 使用 64×64 的调色板索引图。编码时先找 Spalet.e5 中的精确 RGB 颜色；缺少精确颜色时，自动选取 RGB 平方距离最小的现有颜色。同样接近时选择较小的索引，重复保存的结果保持稳定。

该处理只替换输出图片中的索引，不修改 Spalet.e5。RAW 4096/4098 字节条目、已有两字节后缀和 PNG 格式均保持原有结构。缺失或损坏的调色板无法用于可靠编码，仍需补齐或修复资源后保存。

## 兼容与源码

范围扩展继续使用原有 CCZRNG02 / CCZRNG03（footer version 2），没有增加名称池、名称编辑或新范围格式。各版本的特殊范围及中心切换限制继续按原规则执行。

`src/RangeManager.Components` 是共享范围组件，Data 管理器与独立的“攻击穿透范围管理器”都引用这一份实现。独立程序仍可作为兼容入口使用；同一项目应在一个管理器中完成一次编辑和保存，再交给另一个程序打开，避免磁盘基线冲突。

启动环境沿用现有发布策略：Windows x64，需要 .NET 8 Windows Desktop Runtime。范围候选与即时预览的最新验收位于 `验证/2026-11-10-范围候选即时同步`；前一版整合验收保留在 `验证/2026-11-10-范围管理合并` 和 `验证/2026-11-10-合并范围组件`。
